ClaudeClaw OS

A personal AI operating system running locally. It connects Claude AI to Telegram, WhatsApp, a web dashboard, and a schedule system — all routing through a multi-agent architecture with persistent memory.

Quick start Start the system with npm run dev from the project root. The dashboard is at http://localhost:3141. Telegram and WhatsApp activate automatically if their tokens are configured in .env.

Agents

Agents are specialized AI instances, each with a role, a system prompt (CLAUDE.md), and an optional dedicated Telegram token. All run Claude Sonnet 4.6 by default. The Orchestrator handles all unrouted messages and delegates to specialists using @agentName syntax.

@orchestrator
Orchestrator
Main entry point. Handles general queries, decides which specialist to delegate to, manages the overall conversation flow and memory context.
claude-sonnet-4-6
@comms
Comms Agent
Handles communication tasks: drafting emails, writing messages, composing social media posts, and any outbound written communication.
claude-sonnet-4-6
@content

Creates written content: articles, summaries, reports, documentation, scripts, and long-form writing with consistent brand voice.
claude-sonnet-4-6

Manages operations: system tasks, file management, automation scripts, process orchestration, and infrastructure-related work.

Research Agent
Conducts deep research: web search, data analysis, fact-finding, competitive research, and synthesizing information from multiple sources.
claude-sonnet-4-6

Delegating to an Agent

Prefix any message with @agentName to route it to a specific agent:

@research What are the top annuity carriers by market share in 2025?
@comms Draft a follow-up email to a prospect who attended yesterday's seminar
@content Write a 500-word LinkedIn article on retirement income strategies
@ops Create a shell script that backs up the database every night at 2am
No prefix needed If you send a plain message without @agentName, it goes to the Orchestrator, which decides whether to handle it directly or route it automatically.

Skills

Skills are structured prompt templates that give the AI expert-level knowledge and a defined workflow for specific tasks. They are stored in .agent/skills/ and can be invoked via Telegram commands, the dashboard, or by just describing the task.

Automatic skill activation Many skills activate automatically based on your message content — you don't need to explicitly invoke them. The Orchestrator recognizes the intent and loads the relevant skill.

Telegram Bot

Telegram

The Telegram bot is the primary mobile interface for ClaudeClaw OS. Every command, skill, and agent is accessible from your phone. Supports text, voice messages (with Groq Whisper STT), images, and documents.

Setup

1
Create your bot — Open Telegram, message @BotFather, send /newbot, follow the prompts, copy the token.
2
Get your chat ID — Message @userinfobot in Telegram to get your numeric user ID.
3
Configure .env 
TELEGRAM_BOT_TOKEN=1234567890:AAF...
ALLOWED_CHAT_ID=123456789
TELEGRAM_ALLOWED_USERS=yourusername
4
Start the system — Run npm run dev. Open your bot in Telegram and send /start.

General Commands

  • /startInitialize the bot and confirm connection
  • /helpFull command reference
  • /statusSystem status: agent count, token usage, lock state
  • /healthLive API health check for all integrations
  • /statsToday's token and cost usage
  • /agentsList all registered agents
  • /resetClear current session context
  • /abortKill a running task mid-execution
  • /auditLast 10 security and activity log entries

Memory Commands

  • /remember <fact>Save a pinned memory — extracted via Gemini, permanently recalled in future chats
  • /memoryShow top 5 recent memories and latest consolidation insight
  • /pin <id>Pin an existing memory by its ID (get IDs from /memory)
  • /forgetWipe all memory stored for this chat

Skills Commands

  • /skillsList all available skills with descriptions
  • /skill <name>Invoke a skill directly — e.g. /skill git-workflow

Scheduler Commands

  • /tasksList all scheduled tasks with status and next run time
  • /schedule name | cron | promptCreate a scheduled task. Example: /schedule daily-brief | 0 9 * * * | Write a morning AI news briefing
  • /pause <id>Pause a scheduled task
  • /resume <id>Resume a paused task
  • /deltask <id>Delete a scheduled task permanently
  • /missionsList long-running autonomous mission tasks

Voice

  • /voiceToggle voice transcription on/off. When enabled, send voice messages — Groq Whisper converts them to text and processes as normal messages. Requires GROQ_API_KEY in .env.

Security Commands

  • /lockLock the system — no AI responses until unlocked
  • /unlock <PIN>Unlock with PIN (requires PIN_HASH set in .env)

Example Conversations

# Direct question (goes to Orchestrator)
What's the best MYGA rate strategy for a 68-year-old with $400k in a traditional IRA?

# Agent delegation
@research Find the top 5 annuity carriers by AM Best rating in 2025

# Save a fact to memory
/remember My client John Martinez has a $2,400/month income gap and a 7-year time horizon

# Create a daily briefing task
/schedule morning-brief | 0 8 * * * | Summarize any major financial market news relevant to retirement planning

# Invoke a skill explicitly
/skill annuity-life-insurance-sales
Multiple bot tokens You can assign separate Telegram bots to individual agents via COMMS_TELEGRAM_TOKEN, CONTENT_TELEGRAM_TOKEN, etc. in .env. Each agent then has its own Telegram bot identity.

WhatsApp Bridge

WhatsApp

The WhatsApp bridge mirrors your phone number to ClaudeClaw OS using whatsapp-web.js and a headless Chromium session. It accepts direct messages from an allowlist of phone numbers and routes them through the Orchestrator agent.

Setup

1
Configure allowed numbers — Add your phone number(s) to .env (country code, no +): 
WHATSAPP_ALLOWED_USERS=15551234567
2
Start the system — Run npm run dev. A Chromium instance launches automatically.
3
Scan the QR code — Open the dashboard at localhost:3141 → Services tab → WhatsApp QR. Scan with your phone: WhatsApp → Settings → Linked Devices → Link a Device.
4
Confirm connection — The Services tab shows WhatsApp as Connected. The session is saved locally and persists across restarts.

How it works

BehaviourDetail
Accepted messagesDirect messages from numbers in WHATSAPP_ALLOWED_USERS
GroupsIgnored entirely — direct messages only
Unknown sendersSilently ignored (logged as warning)
RoutingAll messages go through the Orchestrator agent with memory context
OutboxIf WhatsApp is offline, messages queue and flush when reconnected
Session storagestore/whatsapp-session/ — delete to force fresh QR scan

Using WhatsApp

WhatsApp has no slash commands — everything is plain natural language. Just message the linked number like you would a person.

# Ask anything
What should I say to a client who says "I hate annuities"?

# Delegate to a specialist agent
@research What is the current 10-year Treasury yield?

# Multi-step task
Draft a follow-up email for a client meeting I had today.
The client is 67, has $500k in a 401k, concerned about outliving their money.
Re-authentication WhatsApp Web sessions expire. If ClaudeClaw shows WhatsApp as disconnected, go to the dashboard Services tab to scan a fresh QR code. If no QR appears, delete store/whatsapp-session/ and restart with npm run dev.

Memory System

ClaudeClaw OS maintains persistent memory across all conversations using Gemini text-embedding-004. Memories are stored in a SQLite database, embedded as vectors, and recalled automatically based on semantic relevance to each new message.

How memories are created

  • Automatic — Every conversation turn is analyzed and facts are extracted silently in the background
  • Manual via Telegram — /remember <fact> pins a memory at importance 0.9+
  • Manual via Dashboard — Memory tab → add memory text field
  • Consolidation — A background loop periodically synthesizes multiple memories into insight summaries

Memory lifecycle

StageWhat happens
IngestGemini extracts summary, entities, topics, importance score from conversation
EmbedSummary is embedded as a 768-dim vector via text-embedding-004
RecallOn each new message, top-N semantically similar memories are prepended as context
ConsolidatePeriodic loop groups related memories and writes insight summaries
DecayLow-importance, old memories are pruned; pinned memories persist forever

Scheduler

The scheduler runs cron-based tasks that execute prompts through the AI agents on a set schedule and deliver results back to your Telegram chat (or log them if no chat is configured).

Creating a scheduled task

Via Telegram:

/schedule <name> | <cron expression> | <prompt>

# Examples
/schedule morning-brief | 0 8 * * * | Summarize the top financial news relevant to retirement planning

/schedule weekly-review | 0 9 * * MON | Create a weekly summary of my recent conversations and any action items

/schedule market-check | 0 16 * * 1-5 | What happened in the bond market today?

Via Dashboard: Tasks tab → New Task form → fill in name, prompt, cron expression, and agent.

Cron expression reference

ExpressionMeaning
0 8 * * *Every day at 8:00 AM
0 9 * * MONEvery Monday at 9:00 AM
0 16 * * 1-5Weekdays at 4:00 PM
0 */4 * * *Every 4 hours
30 12 1 * *First of the month at 12:30 PM

Security

Access control

All messaging interfaces enforce an allowlist. Set these in .env:

ALLOWED_CHAT_ID=123456789         # Telegram chat ID
TELEGRAM_ALLOWED_USERS=username    # Telegram username or user ID
WHATSAPP_ALLOWED_USERS=15551234567 # WhatsApp phone number

PIN lock

Generate a PIN hash and set it in .env to enable system locking:

# Generate PIN_HASH (replace "yourPIN" with your actual PIN)
echo -n "salt:$(echo -n 'salt+yourPIN' | sha256sum | cut -d' ' -f1)"

Then in Telegram: /lock to lock, /unlock yourPIN to unlock.

Kill phrase

Set KILL_PHRASE in .env to an exact phrase that triggers emergency shutdown when spoken in any chat.

Idle lock

Set IDLE_LOCK_MINUTES=30 to auto-lock after inactivity. Default is 30 minutes.

Never expose your dashboard publicly The dashboard at port 3141 has no authentication by default (dev mode). Set DASHBOARD_TOKEN in .env to require a bearer token on all API calls if you expose it beyond localhost.
